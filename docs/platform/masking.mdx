---
title: "Masking Sensitive Identifiers"
description: "Reversible masking of pod, cluster, and account identifiers before external LLM calls."
---

## Overview

OpenSRE can mask sensitive infrastructure identifiers (pod names, cluster names,
hostnames, account IDs, service names, IP addresses, emails) **before** sending
text to an external LLM, then restore the originals in user-facing output. Teams
can use external models while keeping raw identifiers inside the agent runtime.

Masking is **off by default**. Turn it on with environment variables — no code
changes required.

## How it works

1. With masking enabled, the shared CLI LLM runner redacts recognized secret
   assignments and known credential formats before building any identifier map.
2. It replaces identifiers with placeholders such as `<POD_0>`,
   `<NAMESPACE_0>`, or `<CLUSTER_1>` throughout the outgoing prompt, including
   conversation history and tool results.
3. The placeholder-to-original map stays in local memory for that request;
   it is not sent to the model or saved in session state.
4. Replies restore identifiers locally, including JSON tool arguments before
   host execution and final answers before display. Secrets stay redacted.

The same identifier has one placeholder within a request. Each request builds
a fresh map from local history, so placeholder numbers can change between turns
without sharing mappings across concurrent requests.

This boundary covers Copilot and other providers using the shared CLI runner.
It does not add universal masking to direct HTTP SDK providers. Selected
GitHub / Sentry fix tools and agent-exec paths retain their existing opt-in
masking behavior. Environment policy is read for each request.

Plain-text CLI streaming is buffered while masking is enabled, so split
placeholders and secret values are processed before display. With masking
disabled, the runner retains its existing behavior, including streaming.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `OPENSRE_MASK_ENABLED` | `false` | Master switch. Set to `true` / `1` / `yes` / `on` to activate masking. |
| `OPENSRE_MASK_KINDS` | `pod,namespace,cluster,hostname,account_id,ip_address,email,service_name` | Comma-separated list of identifier kinds to mask. Unknown kinds are ignored with a warning. Empty value uses all defaults. |
| `OPENSRE_MASK_EXTRA_REGEX` | *(empty)* | Optional JSON object mapping a label → regex for custom identifiers. Example: `'{"jira_key": "\\\\b[A-Z]+-\\\\d+\\\\b"}'`. Group 1 of the regex, if present, defines the span to mask. |

## Built-in identifier kinds

| Kind | Example input | Example placeholder |
| --- | --- | --- |
| `pod` | `etl-worker-7d9f8b-xkp2q` | `<POD_0>` |
| `namespace` | `kube_namespace:tracer-test` | `kube_namespace:<NAMESPACE_0>` |
| `cluster` | `eks_cluster:prod-us-east-1` | `eks_cluster:<CLUSTER_0>` |
| `service_name` | `service:checkout-api` | `service:<SERVICE_NAME_0>` |
| `hostname` | `kind-control-plane`, `ip-10-0-1-23.ec2.internal` | `<HOSTNAME_0>` |
| `account_id` | `123456789012` | `<ACCOUNT_ID_0>` |
| `ip_address` | `192.168.1.50` | `<IP_ADDRESS_0>` |
| `email` | `alice@example.com` | `<EMAIL_0>` |

## Round-trip guarantee

Identifier masking is reversible. The CLI boundary processes JSON string values
structurally to preserve quotes and backslashes in restored tool arguments;
JSON whitespace may change. Secret redaction is deliberately not reversible.
Custom regex patterns should narrowly identify values, not protocol names or
entire JSON documents.

Secret detection is pattern-based, not a guarantee that every possible secret
will be recognized. It covers the shared credential patterns and labeled
values such as `API key: ...`, `password=...`, and `access_token`. Keep tool
credentials in private integration configuration rather than prompt text.
This change does not scrub existing logs or prevent a vendor CLI from adding
its own metadata outside the OpenSRE prompt.

## Relationship to guardrails

Masking is complementary to the one-way `GuardrailEvaluator`. Guardrails handle
hard-block rules (credit cards, API keys) and replace matches with `[REDACTED]`
irreversibly. Masking handles infrastructure identifiers reversibly so they can
be restored for user-facing output.

Both can be active together. The shared CLI runner applies guardrails before
its request-local secret redaction and identifier masking.

## Example

```bash
export OPENSRE_MASK_ENABLED=true
export OPENSRE_MASK_KINDS=pod,namespace,cluster,hostname
opensre ask "why is the checkout pod crash-looping?"
```

When masking runs on a call path, the LLM sees masked identifiers; output
paths that unmask show the original pod, namespace, and cluster names in the
final answer.

```text
Original: Pod backend-123 failed. API key: secret-value
LLM sees: Pod <POD_0> failed. API key: [REDACTED]
You see: Pod backend-123 failed. API key: [REDACTED]
```
